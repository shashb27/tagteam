# M1 Implementation Guide — product hardening, zero-admin

**Scope:** SQLite persistence, local-account auth, context redaction, observability, abuse guards. Still single-process, still no build step, still zero admin/budget.

## 1. Order of work

1. `server/db.js` + schema + migrations (task 1.1) — backend.
2. Write-through in `sessions.js` (task 1.2) — backend.
3. Restart-resume test (task 1.3) — qa — **gate before auth**: persistence must be solid first.
4. `server/auth/` (tasks 1.4–1.7) — backend + security + frontend.
5. `server/redact.js` (tasks 1.8–1.9) — backend + security + frontend.
6. `server/observe.js` (tasks 1.11–1.13) — backend.
7. `server/guard.js` (tasks 1.14–1.17) — backend + security.
8. M1 gates (tasks 1.19–1.21) — qa, critic, boss.

## 2. `server/db.js`

```js
import Database from 'better-sqlite3';
import path from 'node:path';
const db = new Database(path.resolve(process.env.DATA_DIR || 'data', 'tagteam.db'));
db.pragma('journal_mode = WAL');
db.pragma('foreign_keys = ON');
export const migrations = [`CREATE TABLE users (...); ...`];  // see architecture §8

export const stmts = {
  createUser: db.prepare('INSERT INTO users ...'),
  // ...one prepared statement per query

```

Fallback: detect `better-sqlite3` install failure in `package.json` postinstall → install `sql.js` → same schema, same prepared-statement interface wrapped. Documented in `DEPLOY.md`.

## 3. Write-through in `sessions.js`

Every mutation (`createSession`, `createParticipant`, `createInvite`, `appendMessage`, `revoke`) runs inside `db.transaction(() => { mutate memory; write sqlite; })`. On boot, `loadFromDisk()` rebuilds the in-memory Maps from SQLite. Tests: kill -9 the process, restart, assert state intact.

## 4. `server/auth/local.js` (OIDC-shaped interface)

```js
export const AuthProvider = {
  async register({email, password, name}) {
    if (failRateLimit(email)) throw TooMany;
    const passhash = await bcrypt.hash(password, 12);
    const user = stmts.createUser.run({id: uuid(), email, name, passhash});
    return setCookie(user);
  },
  async login({email, password}) {
    const user = stmts.findUserByEmail.get(email);
    if (!user || !(await bcrypt.compare(password, user.passhash))) { noteFail(email); throw BadCreds; }
    return setCookie(user);
  },
  logout(req) { clearCookie(); },
  currentUser(req) { const sid = cookie(req); return stmts.findAuthSession.get(sid)?.user ?? null; },
};
```

- Cookie: `tt_sid`, httpOnly, Secure iff `BASE_URL` starts `https`, SameSite=Lax, 7d, rotated on login.
- Rate limit: 10 failed logins / IP / 10min → 15-min lockout.
- `POST /api/sessions` and WS guest join require `currentUser(req)`; participant gets `userId`.

## 5. `server/redact.js`

```js
const PATTERNS = [
  /sk-ant-[A-Za-z0-9-_]+/g,
  /sk-[A-Za-z0-9]{20,}/g,
  /Bearer\s+[A-Za-z0-9._-]+/gi,
  /password\s*[:=]\s*\S+/gi,
  /\/Users\/\S+|\/home\/\S+|C:\\\\Users\\\\\S+/g,
];
export function redactForGuest(text) {
  let out = text;
  for (const re of PATTERNS) out = out.replace(re, '[redacted]');
  return out;
}
export function applyHiddenRanges(text, ranges) { /* replace ranges with [hidden by host] */ }
```

Applied in `serializeMessage` when the recipient is a guest. Host sends `hide_range` frame → stored on `participant.hiddenRanges` → applied at delivery.

## 6. `server/observe.js`

- pino logger `log.info({sessionId, userId, kind}, 'event')`.
- `/metricsz` returns `{sessions, activeConnections, messagesTotal, errorsTotal, avgRunMs}` from in-memory counters.
- `audit_events` insert on: session_create, join, revoke, login_success, login_fail, error, redaction_triggered.

## 7. `server/guard.js`

- Token bucket per IP (Map in memory, swept every 5min): session-create 10/min, message 60/min.
- Origin allowlist: `ALLOWED_ORIGINS` env (default localhost+LAN).
- CSRF: `tt_csrf` cookie + `X-CSRF-Token` header; double-submit on all `POST /api/*`.
- Caps: 25 sessions, 5/origin, 2 guests/session (existing), 10 failed logins/IP/10min.

## 8. M1 gates

- Restart-resume E2E: two browsers active, kill server, restart, reload, full transcript + identities intact.
- Redaction E2E: host pastes `sk-ant-xxx`, guest transcript shows `[redacted]`, host sees raw.
- Abuse E2E: 100 rapid `POST /api/sessions` from one IP → 429 after 10.
- Critic sign-off: no secrets in guest-visible transcript; auth cookies set correctly; audit log populated; rate limits fire. → boss merges.
