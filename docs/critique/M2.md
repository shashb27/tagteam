## NITs (non-blocking)

1. **`DEPLOY.md` troubleshooting row 7 is wrong about `LOG_DIR`.** Line 81 claims "the M2 logger writes to `<cwd>/logs` … not the `LOG_DIR` env var. `LOG_DIR` is reserved for a future code change." This is **false**: `server/observe.js:15` *does* read `process.env.LOG_DIR`, and the Dockerfile sets `LOG_DIR=/logs` (line 19), so logs land in the mounted `/logs` volume. The troubleshooting advice ("rely on `docker logs tagteam` or add `- ./logs:/app/logs`") would mislead an operator who sees an empty `./logs` on the host — the real cause would be a missing volume mount, not a logger bug. Fix the row to say logs go to `$LOG_DIR` (default `/logs` in the container) and that an empty host `./logs` means the volume mount is missing or the path was overridden.

2. **`.env.example` lines 36-39 comment is stale.** Same root cause: it says `LOG_DIR` is "reserved for when the logger honors it" — but the logger honors it today. Either drop the "reserved" framing or point readers at `server/observe.js`.

3. **Mobile breakpoint spec drift.** `docs/implementation/M2.md §3` and `architecture.md §2` both say participants collapse to a drawer "**<640px**", but `web/style.css:525` uses `@media (max-width: 760px)`. 760px is the de-facto standard and the wider breakpoint is harmless, but the docs should say 760px (or the CSS should move to 640px). Pick one and reconcile.

4. **`M2.md §1` Dockerfile snippet is stale.** It shows `FROM node:20-slim` and no `LOG_DIR` env; the real `Dockerfile` uses `node:20-bookworm` + build tools and sets `LOG_DIR=/logs`. The guide doc should match the shipped file (or be marked as "sketch — see Dockerfile").

5. **Composer "sticky" is structural, not `position: sticky`.** `style.css:398` uses `flex:none` in a flex column, which keeps the composer pinned to the viewport bottom — functionally equivalent to sticky and passes the a11y/mobile gate, but if someone reads "composer sticky" literally they won't find `position: sticky`. Cosmetic doc/code wording mismatch only.
