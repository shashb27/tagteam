## Previous BLOCKERs — status

1. **auth leak (`GET /api/sessions`)**: **fixed** — `server/index.js:236-257`
   now calls `AuthProvider.currentUser(req)`, returns `401
   {error:'not_authenticated'}` when absent, and filters the list to sessions
   where the caller is `hostUserId` or a participant `userId`. Verified live:
   `MOCK_CLAUDE=1 PORT=3992 node server/index.js` then `curl -s
   http://localhost:3992/api/sessions` → `401 {"error":"not_authenticated"}`.
   No cross-user enumeration, no host keys, no transcript text in the payload.

2. **gate E2Es**: **fixed** — `test/e2e/` now contains `redaction.spec.js`,
   `abuse.spec.js`, `resume.spec.js` alongside the two `two-browser*.spec.js`.
   All three assert the real gate behavior (not trivial passes):
   - `redaction.spec.js`: host transcript contains `sk-ant-test-...` and
     `password=secret123`; guest transcript contains `[redacted]` and does
     NOT contain the raw secret. ✓
   - `abuse.spec.js`: 100 `POST /api/sessions` from one pinned XFF IP →
     `created === 10`, `limited === 90`, `Retry-After` header/body present. ✓
   - `resume.spec.js`: context A starts session + sends "What's the KV cache
     bandwidth issue?"; context B logs in with the same account, hits
     `GET /api/sessions` (200, `count >= 1`), copies `tagteam.v1`
     sessionStorage creds, reloads, and sees both the original prompt and the
     mock `kv_cache_gather` reply in the transcript. ✓
